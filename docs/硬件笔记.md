# 硬件笔记：参数、接线、坑

## 电机（必晖套装：N20 霍尔编码器电机，6V 300 转，减速比 1:50）
- **线序以编码器板上的丝印为准**，丝印是 `M2 VCC C2 C1 GND M1`。线的颜色只作参考，不同批次可能不一样。
- **黑线是编码器电源正极（VCC），蓝线才是地（GND）**，和"黑线接地"的习惯正好相反。编码器电源接反可能直接烧掉霍尔芯片。
- 红线和白线是电机线（M1、M2），上面会有电池的 8.4V，**绝对不能碰 ESP32 的引脚或 3.3V 线**。辨认方法：万用表电阻档量，电机线两两之间有一个比较小的阻值，编码器线之间没有。
- 黄线和绿线是 A、B 两相（C2、C1）。接反了只是计数方向反过来，程序里改一个符号即可。
- 编码器板**自带上拉电阻**，可以直接接单片机。**编码器供电接 3.3V**，输出电平正好匹配 ESP32。
- 插头是 ZH1.5 六针，针距 1.5mm，插不进 2.54mm 洞洞板。配的线另一头是镀锡裸线头，直接焊到洞洞板上即可。
- 尺寸：输出轴直径 3mm，D 型（削边约 2.4mm），长 10mm；减速箱 9mm，电机 15mm，加编码器总长约 21.5mm。编码器插头朝侧面引出（L 型），两个电机背靠背装时插头要错开。
- 性能估算：6V 版接 7.4–8.4V，空载约 370–420 转/分；配 42mm 轮子，空载车速约 0.88 m/s，带负载约 0.7 m/s。巡航 0.38 m/s 约用一半油门，快档的 0.5–0.65 m/s 还在能力范围内。
- 12V 版和 6V 版是同一种电机，只是标的额定电压不同：同为 1:50，6V 版在 6V 下 300 转，12V 版在 12V 下 600 转。放到 8V 左右的电池上，两者转速一样。
- 扭矩：1:50 最大效率点约 0.14 kg·cm，堵转约 0.7 kg·cm（6V）。每轮实际需求约 0.08 kg·cm（车重 350g、加速度 2 m/s² 估算）。
- 电流：6V 堵转约 0.4A，接 8.4V 约 0.6A；TB6612 每路持续 1.2A，够用。车卡住堵转时间长了电机会发热，程序里可以检测"PWM 很大但编码器不动"就断电。
- 编码器精度：7 PPR × 50 = 每轮转一圈 350 个脉冲，四倍频 1400 个，相当于车每走 1mm 记约 10 个数。用 ESP32 的 PCNT 硬件计数器。

## 车体几何
- 两个电机背靠背装，轮距约 90–100mm，车宽约 11cm，和仿真器里设的（轮距 100mm、车身 120×110mm）基本一致。
- 赛道通道 30 cm：车两侧各留约 9.5 cm；车身对角半长约 8.1 cm，原地转弯不会扫墙。
- 车身尽量以车轮轴为中心，原地转弯时才不会扫到墙。
- 电池尽量压在驱动轮轴上方，让驱动轮吃重，防止打滑。
- 万向轮：车底板离地估算 13–14mm（轮子半径 21mm 减去支架处电机轴心离底面约 7–8mm，有 ±2mm 误差）。买的是 N20 迷你牛眼万向轮（圆形、方形各 1 个），**到货后量一下高度，用 M3 尼龙垫片垫到合适高度**。前后差 2mm 只会让车身倾斜不到 2°，对测距影响可以忽略。

## ESP32-S3（选 N8R2 焊好排针版）
- 不用的引脚：GPIO0、3、45、46（启动配置）；GPIO19、20（USB）。如果换成 N16R8，八线 PSRAM 还会占掉 GPIO33–37。
- 实际买到的是 VCC-GND 的 **YD-ESP32-S3**（背面丝印 YD-ESP32-23 2022-V1.3），排针和 DevKitC-1 相同，两排间距 10 孔，板载 RGB 灯在 GPIO48。两个 USB-C：COM 口走 CH343 串口芯片（推荐），USB 口是芯片自带的 USB。IN-OUT、USB-OTG 两处焊盘保持断开。
- 引脚按洞洞板布局分配（11/10 改过一次，让大部分线横平竖直）：TB6612 4/5/6/7/15/16/17，I2C SCL 42 / SDA 41，XSHUT 40/39/38，左编码器 10/9，右编码器 14/13，拨码 47/21，启动键 2（板载 BOOT 键也能用），电池分压 1。布线图见 `firmware/board/board.html`，`layout.py` 会核对它和 `config.h` 是否一致。状态灯用板载 RGB 灯，不另接 LED。
- Arduino IDE 要装 esp32 开发板包 **3.x**；开发板选 ESP32S3 Dev Module，Flash 8MB。
- **电池电压检测必须用 ADC1 的引脚**：ADC2 和 WiFi 共用硬件，WiFi 开着时 ADC2 的读数可能直接失败。
- 用了 WiFi 的话：WiFi 协议栈跑在核 0，控制循环固定在核 1；ESP32 旁边加一颗电容，防止 WiFi 发射时的电流尖峰把主控拉到重启。

## 供电
- 两节 18650 串联，7.4V 标称，充满 8.4V。电池在京东自营买的神火正品。
- 5V 降压只用**固定 5V 输出**的模块。可调款出厂电压不确定，没量就接上 ESP32 会直接烧掉。（宣讲会推荐的 LM2596 一类大多是可调款，同理要先量再接。）
- Mini560 输入不能低于 7V。两节 18650 降到 7V 左右就该充电了，那时车速本来也会明显变慢。**每次测试前把电池充满。**
- 电池接口用防反插接头（XH2.54）。

## VL53L0X 激光测距
- 视场角 25°，默认模式单次测量约 30–33ms，量程约 1.2m。
- 供电接 **3.3V**，不接 5V：XSHUT 由 ESP32 直接驱动，模块按 5V 供电时 XSHUT 上拉到 5V，会往 ESP32 引脚里灌电流。
- 必须买带 XSHUT 引脚的 6 针模块。几个传感器默认地址都是 0x29，只能用软件改：开机时先用 XSHUT 让其他传感器保持复位，逐个唤醒、逐个改地址。
- 新模块镜头上可能贴着保护膜，忘了撕会读数异常。
- 安装：**左右两颗装在车轮轴正上方**，离车中线约 45mm；前方那颗在车轮轴前方约 55mm；离地 5–10cm（太低会受地面反光干扰，太高可能打到墙顶的锡箔胶带）。装法不同就改 `BrainParams` 里对应的数。
- 30 cm 通道里的理论读数：车在通道正中时，侧面约 102 mm；前方停车点（车轴到格子中心）约 92 mm；侧面有开口时读数跳到 400 mm 以上。
- 一两厘米宽的墙缝基本看不出来：10cm 外光斑约 4–5cm 宽。真正的问题正好相反：光锥太宽，会扫到路口处横着伸出去的墙，让开口看起来"开得晚"。大脑里已经用"吸附到网格"处理了。

## WiFi 调试
- **主办方已确认：调试时可以用，比赛时必须关掉。**固件留一个比赛版，彻底不开 WiFi；比赛当天只烧这个版本。
- 用途：
  1. 实时遥测：电脑上看三个测距读数、航向、状态和每个决策。
  2. **录下真车输入，回到电脑上喂给同一份 brain.cpp，一字不差地复现真车的每个决定**，还能拿这些数据校准仿真器。
  3. 在线调参，不用每次都重新烧录。
  4. 无线烧录（OTA）。
  5. 测试时远程急停。
- 方案：车自己开热点（或用手机热点，别连需要认证的校园网，ESP32 也只支持 2.4GHz）；车用 UDP 发数据，电脑上用 Python 接收、画图、存文件。
- WiFi 只用来"看"，不进控制回路。

## 用真车数据校准仿真器（车装好后各花一两分钟）
| 测什么 | 怎么测 | 校准什么 |
|---|---|---|
| 电机 | PWM 从 0 跳到 0.5，记录编码器转速 | 死区、最高速度、响应快慢、左右轮快慢差 |
| 陀螺仪 | 车静止放一分钟 | 零漂 |
| 测距 | 沿墙开过一个路口 | 开口处读数的真实变化曲线 |
| 地面 | 在真实场地猛起步、急停 | 打滑程度（摩擦系数） |

## 往届对手
三届照片里几乎全是黄色轮子的 TT 马达套件车：超声波或红外开关、没有编码器、转弯大多靠定时。今年宣讲会推荐的也是这一档：STC89C52 或 STM32F103C8T6，TB6612 或 L298N，LM2596 降压，示例程序是"前面没墙就直行，否则左、右、掉头"。赛道没有岔路，这种车也能走完，所以拉开差距靠的是速度和不碰墙。我们的车价格和他们在同一档，钱花在感知（激光测距、陀螺仪、编码器）上，硬件优势最终要靠软件才能兑现。
